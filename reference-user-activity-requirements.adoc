= Exigences de détection de l'activité des utilisateurs pour NetApp Ransomware Resilience
:hardbreaks:
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
NetApp Ransomware Resilience user activity detection vous permet de répondre aux événements de ransomware au niveau de l'utilisateur. Vous devez créer un tenant et un ensemble d'agents pour activer la détection de l'activité utilisateur. Avant d'activer la détection, vous devez vous assurer que vous respectez les exigences relatives au système d'exploitation, au serveur et au réseau décrites afin que Ransomware Resilience puisse détecter et signaler correctement les événements.



[[user-activity-tenant]]
== locataire d'activité utilisateur

Pour activer la détection de l'activité des utilisateurs, un tenant est configuré afin de permettre le partage des événements d'activité avec Ransomware Resilience. Vous pouvez sélectionner la région et le fournisseur de cloud dans lesquels vous souhaitez que Ransomware Resilience déploie le tenant.


NOTE: Le déploiement régional du locataire n'a aucune incidence sur le Console agent. Le déploiement du Console agent est indépendant de ces régions.

Le locataire peut être déployé sur AWS et Azure dans les régions suivantes :

|===
| Fournisseur de cloud | Région 


| AWS  a| 
* Asie-Pacifique (Sydney) (ap-sud-est-2)
* Europe (Francfort) (eu-central-1)
* États-Unis Est (Virginie du Nord) (us-east-1)




| Azuré | Est des États-Unis 
|===


[[user-activity-agent-requirements]]
== Exigences relatives à l'agent d'activité utilisateur

Après la création du locataire, vous devez créer un agent d'activité utilisateur pour activer la détection de l'activité utilisateur. L'agent d'activité utilisateur n'est pas le Console agent ; l'agent d'activité utilisateur doit être déployé comme une instance de calcul distincte.

Assurez-vous que votre agent d'activité utilisateur réponde aux exigences suivantes et respecte les recommandations.



[[operating-system-requirements]]
=== Configuration requise pour le système d'exploitation

La détection des comportements suspects des utilisateurs est prise en charge avec les systèmes d'exploitation suivants :

[cols="2"]
|===
| Système opérateur | Versions prises en charge 


| AlmaLinux | 9.4 (64 bits) à 9.5 (64 bits) et 10 (64 bits), y compris SELinux 


| CentOS | CentOS Stream 9 (64 bits) 


| Debian | 11 (64 bits), 12 (64 bits), y compris SELinux 


| OpenSUSE Leap | 15.3 (64 bits) à 15.6 (64 bits) 


| Oracle Linux | 8.10 (64 bits) et 9.1 (64 bits) à 9.6 (64 bits), y compris SELinux 


| Red Hat Enterprise Linux | 8.10 (64 bits), 9.1 (64 bits) à 9.6 (64 bits) et 10 (64 bits), y compris SELinux 


| Rocheux | 9.4 (64 bits) à 9.6 (64 bits), y compris SELinux 


| SUSE Linux Enterprise Server | 15 SP4 (64 bits) à 15 SP6 (64 bits), y compris SELinux 


| Ubuntu | 20.04 LTS (64 bits), 22.04 LTS (64 bits) et 24.04 LTS (64 bits) 
|===

NOTE: L’ordinateur que vous utilisez pour l’agent d’activité de l’utilisateur ne doit pas exécuter d’autres logiciels au niveau de l’application. Un serveur dédié est recommandé.

La  `unzip`commande est nécessaire pour l'installation. La  `sudo su -`commande est nécessaire pour l'installation, l'exécution de scripts et la désinstallation.



[[server-requirements]]
=== Configuration requise pour le serveur

Le serveur doit répondre aux exigences minimales suivantes :

* **Processeur** : 4 cœurs
* **RAM** : 16 Go de RAM
* **espace disque** : 36 Go libres




==== Recommandations serveur

* Allouez de l’espace disque supplémentaire pour permettre la création du système de fichiers. Assurez-vous qu’il y a au moins 35 Go d’espace libre dans le système de fichiers. + Si `/opt` est un dossier monté depuis un stockage NAS, les utilisateurs locaux doivent avoir accès à ce dossier. La création de l’agent d’activité utilisateur peut échouer si les utilisateurs locaux ne disposent pas des autorisations nécessaires.
* Installez l'agent d'activité utilisateur sur un système distinct de votre environnement Ransomware Resilience. Si vous installez l'agent et Ransomware Resilience sur la même machine, prévoyez 50 à 55 Go d'espace disque. Sous Linux, allouez 25 à 30 Go d'espace à `/opt/netapp` et 25 Go à `/var/log/netapp`.
* Il est recommandé de synchroniser l'heure à la fois sur le système ONTAP et sur la machine de l'agent d'activité utilisateur à l'aide du protocole NTP (Network Time Protocol) ou du protocole SNTP (Simple Network Time Protocol).




==== Recommandations de dimensionnement

Lors de la collecte d'événements utilisateur, assurez-vous que la machine hébergeant l'agent d'activité utilisateur est dimensionnée pour s'adapter à votre taux d'événements. Cela signifie que vous devez disposer d'un nombre suffisant de collecteurs de données ainsi que de suffisamment de CPU et de RAM sur la machine hébergeant l'agent d'activité utilisateur pour traiter le nombre d'événements par seconde. Pour augmenter le nombre de collecteurs de données, vous devrez peut-être augmenter la RAM ou la capacité du CPU. Ransomware Resilience prend en charge jusqu'à 50 collecteurs de données par agent d'activité utilisateur.

Le tableau suivant fournit des indications générales pour le dimensionnement :

|===
| Configuration de la machine de l'agent d'activité utilisateur | Nombre de collecteurs de données | Taux d'événements maximal 


| 4 cœurs, 16 Go | 10 collecteurs de données | 20 000 événements/seconde 


| 4 cœurs, 32 Go | 20 collecteurs de données | 20 000 événements/seconde 
|===
Vous pouvez également calculer vos besoins spécifiques. Pour déterminer la taille appropriée, il est recommandé d'appliquer une marge de sécurité de 30 %. Utilisez cette formule pour vérifier si votre configuration peut supporter la charge.

[listing]
----
Where E is the sum of all events per second across all data collectors:

E + (0.3 x E) < 20,000 events/second
----
.Calculer le débit de données d'événements dans Ransomware Resilience
[%collapsible]
====
Ransomware Resilience fournit un script que vous pouvez exécuter sur votre système pour calculer le débit des données d'événements. Par défaut, le script s'exécute pour un maximum de cinq SVM. Si votre environnement comprend plus de cinq SVM, vous pouvez modifier le script en conséquence. Quel que soit le nombre de SVM, le script prend environ cinq minutes pour obtenir une mesure du débit moyen d'événements. Avant d'exécuter le script, vous devez disposer des éléments suivants :

* link:suspicious-user-activity.html["Agent d'activité utilisateur configuré"]
* L'adresse IP du cluster
* Nom d'utilisateur et mot de passe de l'administrateur du cluster
* Installé `sshpass` sur la machine Linux (vous pouvez l’installer à l’aide de la commande `sudo yum install -y sshpass`)


.Étapes
. Depuis la machine hébergeant l'agent d'activité utilisateur, exécutez le script en tant qu'administrateur : `/opt/netapp/cloudsecure/agent/install/svm_event_rate_checker.sh`
. Lorsque vous y serez invité, fournissez l'adresse IP du cluster, le nom d'utilisateur administrateur et le mot de passe administrateur.
. L'exécution du script prend environ cinq minutes. Une fois terminée, la ligne de commandes affiche le taux d'événements, par exemple "Svm svm_rate is generating 100 events/sec."
+
Utilisez le taux d'événements pour calculer votre dimensionnement.

=== règles d'accès au réseau cloud

Veuillez consulter les règles d'accès au réseau cloud pour votre zone géographique concernée (Asie-Pacifique, Europe ou États-Unis).


IMPORTANT: Lors de l'installation initiale, remplacez le  `<site_name>` par une autorisation de caractère générique (`*`. Après que l'agent est activé et pleinement opérationnel, vous pouvez remplacer l'autorisation par le nom du site. Contactez votre représentant NetApp pour le nom du site.


NOTE: L'agent d'activité utilisateur utilise la technologie NetApp Data Infrastructure Insights, d'où l'utilisation de  `cloudinsights`points de terminaison. Pour plus d'informations, consultez link:concept-user-behavior.html#user-activity-forensics["Ransomware Resilience et Data Infrastructure Insights"].
